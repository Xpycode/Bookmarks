### Discovered
- **The bookmarklet was already shipped in v2 wave 1** but the user had forgotten — buried inside the Import dialog. Discoverability is its own UX problem; queued as wave 3b T1.
- **Edge "Service Unavailable" on bookmarklet popup** wasn't a server bug — direct `curl` to `?r=quickadd` returns HTTP 200 with the proper login form. Diagnosis: Edge's Tracking Prevention had cached a stale verdict for the popup destination. Cleared via direct visit + cache reset. Safari was fine throughout.
- **Bookmarklet research surfaced a deeper architectural fork** for "save current tab" UX in 2026: bookmarklets get silently CSP-blocked on a growing fraction of sites (GitHub, X, banking, GMail) and have no mobile share-sheet integration. PWA + Web Share Target (manifest.webmanifest + service worker + `r=share` POST route) is the underrated middle path that fits the no-Node/no-build-step constraint. Karakeep + Linkwarden both ship bookmarklet *plus* MV3 extension *plus* PWA. Documented in PROJECT_STATE open questions as wave 3b candidate.
- **`offsetHeight` reads inside the greedy loop force a synchronous layout per iteration** — that's actually the feature, not a bug. With ~30 cards × 5 column-height reads, the layout cost is negligible and the algorithm sees real heights instead of estimates.

### Decisions Made
- Architecture: column-wrapped masonry over flat-container-with-absolute-positioning (logged in `decisions.md`). Reason: column-wrapped composes natively with Sortable's cross-container drag, which we already use for inter-card bookmark drag.
- Persistence: flat order + greedy repack (decision C from spec). Tradeoff documented — drag-target column not guaranteed sticky across reloads. Promote to per-column storage only if it bothers in practice.
- `max-height: 70vh` over fixed-pixel bump or full removal. Adapts to viewport height; preserves "everything in view" for normal cards while keeping the 281-item monster bounded.
