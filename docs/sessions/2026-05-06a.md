### Discovered

- **Strato uses PHP-FastCGI, not mod_php.** Confirmed via three working PHP sites (`grep -rEn "SetHandler|AddHandler|AddType.*php"` returns zero matches across all of them). Adding a mod_php handler directive on a FastCGI host doesn't get ignored — it gets misinterpreted and breaks PHP execution. The "harmless if unused" comment in our v1 `.htaccess` was actively wrong.
- **`x-powered-by: PHP/8.4.20`** is exposed by default on Strato — minor info disclosure (helps attackers pick CVE exploits). Could silence with `header_remove("X-Powered-By");` at top of `index.php`. Low priority but cheap to fix.
- **Inherited `.gitignore` from a cloned framework** (the LLM-Directions `docs/.gitignore` had `sessions/*.md` ignored) silently ate session-log moves in commit `bd02f04`. Lesson: when consuming a vendored/cloned template, audit its `.gitignore` for rules that don't apply to consumers *before* the first commit.
- **Bookmarkninja export attributes that the v1 parser drops:** `ADD_DATE` (Unix timestamp) and `TAGS` (comma-list, e.g. `"favourites, lernen, safari"`). Folder hierarchy and `NOTES` are preserved correctly. The 609-bookmark import committed without these — when we add tags to the schema (v2 backlog item #1), we'll either re-import or write a one-shot SQL/parser pass that backfills tags from a re-parse of the export file.
- **lftp `mirror` without `--delete`** + **stage-then-mirror** = bulletproof preservation of server-side data. The redeploy of just `.htaccess` was a perfect demo: only the changed file transferred, everything else (including `data/bookmarks.sqlite` already on the server, never even in our source) untouched.
