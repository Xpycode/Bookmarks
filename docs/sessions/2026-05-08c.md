### Discovered
- **Web Share Target sometimes shoves the URL into `text` instead of `url`** on Android Chrome. `share.php` falls back: if `url` is empty and `text` validates as a URL, treat `text` as the URL.
- **`Service-Worker-Allowed` header workaround not needed** when SW is at root path. Root scope is automatic. We only would have needed it if shipping `sw.js` from `/public/sw.js`.
- **lftp's mirror only re-uploads files whose mtime/size changed**, which means the asset-cache-bust `?v=<filemtime>` only advances on actual content changes — exactly what we want. Three deploys this session, each only re-uploading files I'd actually modified.

## 3a-followup: per-column drag persistence (post-session reopen)

User flagged the drag was "chaotic" — moving one card cascaded into total reshuffles of unrelated cards, and reloads put dragged cards back in wrong columns. Diagnosed as the documented decision-C tradeoff from the wave-3a spec: greedy packing was the source of truth for column placement, so any new flat order produced a different greedy result.

### Fix
- New `view.dashboard_columns` JSON key (array of arrays of cat IDs, one per column) — now the source of truth.
- New `set_view_columns` API endpoint mirroring `set_view_order`.
- `layoutDashboard()` rewritten: prefers `dashboard_columns` when its length matches current `colCount`; greedy is fallback (no saved layout / column-count mismatch / new cats not in saved). Greedy result auto-persisted via `saveDashboardColumns()` so subsequent renders use the fast path.
- `Sortable.onEnd` simplified: persist column membership, **no post-drop `layoutDashboard()` call**. Cards stay exactly where Sortable dropped them.
- Flat `dashboard_order` still kept in sync (zigzag flatten) — used as the seed for greedy when column count changes via resize.
- Stale ids in `dashboard_columns` (deleted/hidden cats) are silently skipped via `cardById` lookup — means showing-back a previously-hidden card returns it to its exact original column position. Layout has memory.

### Tested
User confirmed live: drag is stable, no cross-column cascade, drop position survives reload.

### Decision logged
`decisions.md` → "Promoted dashboard layout from flat-order to per-column persistence." Reverses wave-3a decision C entirely.
